# フォルダ構成ガイド

このドキュメントでは、Reminoteプロジェクトの各フォルダの役割と内容について説明します。

## 📁 プロジェクト全体の構成

```
Reminote/
├── api/                 # バックエンドAPI
├── app/                 # フロントエンドアプリ
├── docs/                # ドキュメント
├── shared/              # 共通ライブラリ
├── .gitignore           # Git除外設定
├── env.example          # 環境変数テンプレート
├── package.json         # ルートレベルの管理
└── README.md            # プロジェクト説明
```

## 🔧 api/ フォルダ

**役割**: バックエンドAPIサーバー

**内容**:
- Node.js + Express.js で構築されたAPIサーバー
- データベースとの連携
- 認証・認可処理
- ビジネスロジックの実装

**主要ファイル**:
- `src/app.js` - Expressアプリケーションの設定
- `src/server.js` - サーバーの起動処理
- `package.json` - API用の依存関係
- `index.js` - エントリーポイント

**開発時の注意点**:
- 環境変数（`.env`）で設定を管理
- データベース接続の設定
- CORS設定でフロントエンドとの連携
- エラーハンドリングの実装

## 📱 app/ フォルダ

**役割**: フロントエンドモバイルアプリ

**内容**:
- React Native + Expo で構築されたモバイルアプリ
- ユーザーインターフェース
- APIとの通信
- 状態管理

**主要ファイル**:
- `app.json` - Expo設定ファイル
- `_layout.tsx` - アプリのレイアウト設定
- `(tabs)/` - タブナビゲーション
- `components/` - 再利用可能なコンポーネント
- `lib/firebase.js` - Firebase設定
- `package.json` - アプリ用の依存関係

**開発時の注意点**:
- TypeScriptを使用
- レスポンシブデザインの実装
- 状態管理（Redux/Context API）
- ナビゲーション設計

## 📚 docs/ フォルダ

**役割**: プロジェクトのドキュメント

**内容**:
- API仕様書
- データベース設計書
- デプロイガイド
- コントリビューションガイド
- アーキテクチャ設計書

**主要ファイル**:
- `README.md` - ドキュメント目次
- `api.md` - API仕様書
- `database.md` - データベース設計
- `deployment.md` - デプロイガイド
- `contributing.md` - コントリビューションガイド
- `architecture.md` - アーキテクチャ設計

**開発時の注意点**:
- コードの変更時にドキュメントも更新
- 図表を使って分かりやすく説明
- 実装例を含める

## 🔄 shared/ フォルダ

**役割**: 共通ライブラリと型定義

**内容**:
- TypeScript型定義
- 共通のユーティリティ関数
- 定数定義
- 共通のインターフェース

**主要ファイル**:
- `types.ts` - TypeScript型定義
- `constants.ts` - 定数定義
- `utils.ts` - ユーティリティ関数
- `interfaces.ts` - インターフェース定義

**開発時の注意点**:
- APIとアプリ間で共有される型定義
- 一箇所で管理して整合性を保つ
- バージョン管理に注意

## 🗂️ その他のファイル

### .gitignore
- Gitで追跡しないファイルを指定
- 環境変数ファイル、ログファイル、ビルド成果物など

### env.example
- 環境変数のテンプレート
- 新しい開発者が設定を理解しやすくする

### package.json（ルート）
- プロジェクト全体の管理
- ワークスペース設定
- 共通のスクリプト定義

## 🚀 開発ワークフロー

### 1. 新機能開発
1. `shared/` で型定義を追加
2. `api/` でAPIエンドポイントを実装
3. `app/` でUIコンポーネントを実装
4. `docs/` でドキュメントを更新

### 2. バグ修正
1. 該当するフォルダで修正
2. テストを追加
3. ドキュメントを更新

### 3. リリース準備
1. 全フォルダでテスト実行
2. ビルド確認
3. ドキュメント最終確認
